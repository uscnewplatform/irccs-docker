= Installazione e Avvio
:description: Guida passo-passo per la prima installazione della piattaforma IRCCS su un nuovo host.

== Prerequisiti

Prima di procedere, assicurarsi che siano installati sul sistema:

* **Docker** e **Docker Compose**
* **Git**
* **OpenSSL** (`openssl`, `openssl-dev`)
* **OpenSSH** (`openssh`)
* Una chiave SSH valida per accedere al repository Git
* Accesso al registro Docker privato Nexus: `nexus.infocube.it`

[TIP]
====
Per effettuare il login al registro Nexus:

[source,bash]
----
docker login nexus.infocube.it
----

Le credenziali vanno richieste al team di sviluppo.
====

== Installazione su Alpine Linux / Proxmox

Per installazioni su container Proxmox con Alpine v3.22, eseguire i seguenti comandi:

[source,bash]
----
apk update && apk upgrade
apk add docker docker-compose
rc-service docker up
rc-service docker start
rc-update add docker
----

Configurare il daemon Docker con log rotation e storage driver:

[source,bash]
----
mkdir -p /etc/docker
cat > /etc/docker/daemon.json << EOF
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "20m",
    "max-file": "3"
  },
  "storage-driver": "vfs"
}
EOF
rc-service docker restart
apk add git
apk add openssl openssl-dev openssh
----

== Avvio rapido del progetto

[source,bash]
----
git clone git@github.com:infocube-it/irccs-docker.git
cd irccs-docker
cp .env_example .env
# Compilare il file .env con i valori forniti dal team di sviluppo
docker compose up -d
----

[WARNING]
====
Il file `.env` contiene credenziali riservate e **non deve mai essere committato** sul repository Git.
Il file `.env_example` fornisce il template con i nomi di tutte le variabili richieste.

== Configurazioni post-avvio

=== 1. Installazione Search Parameters FHIR

Dopo il primo avvio, è necessario installare i parametri di ricerca custom nel server FHIR per garantire il corretto funzionamento dei microservizi.

[source,bash]
----
cd setup
chmod +x install_searchparameters.sh
bash install_searchparameters.sh <hostname>:<port>
----

Sostituire `<hostname>:<port>` con l'indirizzo del container HAPI FHIR (default: `irccs-hapi-fhir:8080`).

=== 2. Configurazione SMTP in Keycloak

. Accedere alla dashboard Keycloak all'indirizzo `http://<host>:9445`
. Autenticarsi con le credenziali di admin definite nel file `.env`
. **Cambiare immediatamente la password** dell'utente admin e assegnargli il ruolo `ADMIN`
. Selezionare il realm `pascale`
. Nel menu laterale: *Realm Settings* → tab *Email*
. Inserire i parametri SMTP forniti dall'infrastruttura
. Verificare la connessione con il pulsante *Test connection*

=== 3. Configurazione lingua e tema Keycloak

. Accedere alla UI di Keycloak (`http://<host>:9445`)
. Selezionare il realm `pascale` → *Realm Settings*
. Tab *Languages*: aggiungere **Italiano**
. Tab *Themes* → *Custom Theme*: selezionare `pascale-theme`

=== 4. Rinnovo/Cambio Client Secret Keycloak

Se si rigenera il client secret di Keycloak:

. Accedere a: Realm `pascale` → *Clients* → `irccs` → *Credentials* → *REGENERATE CLIENT SECRET*
. Copiare il nuovo secret
. Aggiornare la variabile `KEYCLOAK_CLIENT_SECRET` nel file `.env`
. Riavviare lo stack:

[source,bash]
----
docker compose down
docker compose up -d
----

=== 5. Installazione Patient Journey J-LI

[source,bash]
----
cd setup
chmod +x install_jli.sh
./install_jli.sh http://irccs-hapi-fhir:8080/fhir
----

=== 6. Verifica account di servizio Keycloak

Verificare che l'utente di servizio `service-account-irccs` nel realm `pascale` abbia il ruolo `/admin` (necessario per le operazioni di signup).

=== 7. Installazione tipi di consenso (registry)

I tipi di consenso sono un *registry dinamico* persistito come `CodeSystem` FHIR (`urn:irccs:consent-type`). Lo script precarica i 9 tipi base con terminologia HL7 (scope `consentscope`, category `consentcategorycodes`). È necessario per far comparire i tipi nel designer e per garantire che il tipo `privacy` esista (gli studi che lo richiedono lo usano per valorizzare `Consent.scope`/`category`).

[source,bash]
----
cd setup
chmod +x install_consent_types.sh
bash install_consent_types.sh <hostname>:<port>
----

Idempotente (PUT conditional `?url=`): può essere rilanciato senza creare duplicati. Successivamente i tipi sono gestibili a runtime dalla dashboard (Back-office → Tipi di consenso, solo SuperAdmin).

=== 6. Import terminologia LOINC (opzionale)

Per abilitare la validazione e ricerca di codici LOINC nel server FHIR è necessario importare la terminologia.

[IMPORTANT]
====
A partire da LOINC 2.77, il file `MultiAxialHierarchy.csv` è stato rimosso e sostituito da `ComponentHierarchyBySystem.csv`. Tutti i file sono inoltre racchiusi in una cartella con il numero di versione (es. `Loinc_2.82/`). +
Il file `terminology/loincupload.properties` nel repository gestisce già questi mapping — non modificare i path di default senza aggiornare anche questo file.
====

==== Prerequisiti

* Account su https://loinc.org (registrazione gratuita)
* File `Loinc_<version>.zip` scaricato dalla sezione *Downloads* di loinc.org
https://loinc.org/download/loinc-complete/

* `hapi-fhir-cli.jar` della stessa versione del server (es. 8.6.8)
https://github.com/hapifhir/hapi-fhir/releases/download/v8.6.8/hapi-fhir-8.6.8-cli.zip


==== Procedura

Copiare zip, properties e CLI nel container (il CLI **deve girare dentro il container** perché i file > 10 MB vengono referenziati localmente, non trasferiti via HTTP):

[source,bash]
----
docker cp Loinc_2.XX.zip irccs-hapi-fhir:/tmp/
docker cp terminology/loincupload.properties irccs-hapi-fhir:/tmp/
docker cp terminology/hapi-fhir-cli.jar irccs-hapi-fhir:/tmp/
----

Eseguire l'import:

[source,bash]
----
docker exec irccs-hapi-fhir java -jar /tmp/hapi-fhir-cli.jar upload-terminology \
  -d /tmp/Loinc_2.82.zip \
  -d /tmp/loincupload.properties \
  -t http://localhost:8080/fhir \
  -v r4 \
  -u http://loinc.org
----

[NOTE]
====
L'operazione richiede 15-30 minuti. Monitorare i log in un secondo terminale:

[source,bash]
----
docker logs -f irccs-hapi-fhir
----

Completamento confermato da risposta HTTP 200 con `OperationOutcome` di severity `information`.
====

Per aggiornare a una versione LOINC successiva, aggiornare il prefisso di versione (es. `Loinc_2.82` → `Loinc_2.83`) in tutte le righe del file `terminology/loincupload.properties`.

=== 7. Installazione librerie CRF su HAPI FHIR

Le librerie CRF (CTCAE v4/v5/v6, PRO-CTCAE v1, EORTC QLQ-C30/HCC18, EuroQol EQ-5D-5L, USC PROFFIT) sono distribuite come `CodeSystem` FHIR nella cartella `importCrfLibraries/`.
Ogni sotto-cartella contiene uno script di installazione che esegue il push del bundle FHIR su HAPI.

[source,bash]
----
cd importCrfLibraries

# CTCAE v4
bash ctcae-v4/install-ctcae-v4.sh http://irccs-hapi-fhir:8080/fhir

# CTCAE v5
bash ctcae-v5/install-ctcae-v5.sh http://irccs-hapi-fhir:8080/fhir

# CTCAE v6
bash ctcae-v6/install-ctcae-v6.sh http://irccs-hapi-fhir:8080/fhir

# PRO-CTCAE v1
bash proctc-v1/install-proctc-v1.sh http://irccs-hapi-fhir:8080/fhir

# EORTC QLQ-C30
bash eortc-qlq-c30/install-eortc-v1.sh http://irccs-hapi-fhir:8080/fhir

# EORTC QLQ-HCC18
bash eortc_hcc18/install-eortc-hcc18.sh http://irccs-hapi-fhir:8080/fhir

# EuroQol EQ-5D-5L
bash euroqol_eq5d5l/install-euroqol-eq5d5l.sh http://irccs-hapi-fhir:8080/fhir

# USC PROFFIT
bash usc_proffit/install-usc-proffit.sh http://irccs-hapi-fhir:8080/fhir
----

[NOTE]
====
Gli script inviano il bundle FHIR tramite `curl` in modalità `transaction`. +
Se HAPI FHIR restituisce `200 OK` con un `Bundle` di risposta, l'installazione è riuscita. +
Il frontend scopre le librerie automaticamente da HAPI: dopo l'installazione il bottone di import compare nel Questionnaire builder senza modifiche al codice. +
Per i dettagli sull'architettura e la struttura delle librerie, vedere xref:librerie-crf.adoc[Librerie CRF — Gestione e Import].
====

== Abilitazione SSL per Keycloak

Per attivare Keycloak in modalità SSL:

. Fornire certificato e chiave privata tramite volume Docker, riportandoli nel file `keycloak.conf`
. Rimuovere il flag `--start-dev` dall'entrypoint nel `docker-compose.yaml`
. La porta HTTPS di Keycloak passa da `9445` (HTTP) a `8443` (HTTPS)

[NOTE]
====
In ambiente di test può essere necessario aggiungere l'hostname di Keycloak in `/etc/hosts`:

[source]
----
127.0.0.1 keycloak.irccs.infocube.it
----
====

== Disabilitazione del sistema di ticketing

Per disabilitare il modulo Zammad, commentare o rimuovere la variabile `VITE_APP_ZAMMAD_HOST` nel file `httpd-config/config-prod.js`. Questo nasconderà i pulsanti di gestione ticket e bloccherà le chiamate di polling.
