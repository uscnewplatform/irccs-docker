= Keycloak — Identità e Accessi
:description: Configurazione del realm Keycloak, client IRCCS, ruoli e Authorization Services.

== Realm `pascale`

Import automatico da `keycloak-config/realm-export/pascale-realm_2.0.json` con strategia `OVERWRITE_EXISTING`.

[cols="1,2"]
|===
| Parametro | Valore

| Realm name | `pascale`
| SSL Required | `external`
| Access Token Lifespan | 1800 s (30 min)
| SSO Session Max | 36000 s (10 ore)
| OTP Policy | TOTP — HmacSHA1, 6 cifre, 30 s
|===

== Client `irccs`

[cols="1,2"]
|===
| Parametro | Valore

| Client ID | `irccs`
| Access Type | `confidential`
| Service Accounts | Abilitato
| Authorization Services | Abilitato
| Policy Enforcement Mode | `ENFORCING`
| HTTP Method as Scope | `true`
|===

== Ruoli utente

[cols="1,3"]
|===
| Ruolo | Descrizione

| `superadmin` | Accesso completo senza restrizioni gruppo
| `admin` | Amministratore sistema
| `sperimentatore_pi` | Principal Investigator (composito, include `sperimentatore`)
| `sperimentatore` | Ricercatore
| `radiologo` | Accesso immagini DICOM
| `frontOffice` | Operatore front-office
| `backOffice` | Operatore back-office
|===

=== Ruoli FHIR fine-grained

Convenzione `+{ResourceType}:{operation}+` — es. `Patient:read`, `Task:create`, `Questionnaire:read`.
Assegnati come sotto-ruoli dei ruoli standard compositi.

== Authorization Services — Risorse

[cols="2,3,1"]
|===
| Risorsa | URI | Scope

| Admin Resource | `*` | GET POST PUT DELETE
| AuthGroup Resource | `/fhir/auth/groups`, `/fhir/auth/groups/*` | GET POST PUT DELETE
| Dicom Resource | `/fhir/dicom/*` | GET POST PUT DELETE
| TOTP Resource | `/totp/*` | POST
| Create \{Type} Resource | `/fhir/\{Type}` | GET POST
| Base \{Type} Resource | `/fhir/\{Type}/\{id}` | GET PUT DELETE
| Search \{Type} Resource | `/fhir/\{Type}/_search` | GET
| History \{Type} Resource | `/fhir/\{Type}/_history` | GET
|===

NOTE: Con `policyEnforcementMode: ENFORCING`, qualsiasi risorsa senza una permission esplicita viene negata. Aggiungere sempre sia la risorsa sia la permission.

== Service Account

I microservizi di sistema (es. `irccs-microservice-crf-tac`) usano il service account tramite `ServiceAccountTokenProvider` per operazioni che bypassano il filtro `group_ids`. Il token è ottenuto via client credentials flow e cachato automaticamente.

== Aggiungere un nuovo ruolo/permesso

. Keycloak Admin Console → realm `pascale`
. **Roles** → crea ruolo fine-grained (es. `DocumentReference:create`)
. Assegnalo al ruolo composito appropriato
. **Clients** → `irccs` → **Authorization** → verifica/crea risorsa per il path
. **Authorization** → **Permissions** → crea permission (risorsa + policy)
. Esporta realm aggiornato in `keycloak-config/realm-export/pascale-realm_2.0.json`

== Creazione Provider "scan-claims"

Per installare il provider `scan-claims` su Keycloak e aggiungerlo al client IRCCS:

1. Eseguire `/opt/keycloak/bin/kc.sh build` da dentro il container.
2. Andare in console **Clients** → **irccs** → **Client scopes** → **irccs-dedicated** → **Add mapper** e aggiungere scan session (`patientid/study/id`) con nome `scan-claims`.

Comparirà il QR code per il provider `scan-claims`.
