= Microservizi
:description: Descrizione dettagliata di ogni microservizio Quarkus della piattaforma IRCCS.

== Panoramica

I microservizi sono applicazioni **Quarkus** pubblicate sul registro privato `nexus.infocube.it` e orchestrate tramite Docker Compose.
Tutti i microservizi (eccetto Notification) condividono la stessa configurazione base in `microservice-config/application.properties`, che sovrascrive e integra le proprietà interne (`application.properties` embedded nell'immagine).

[NOTE]
====
Le proprietà nel file `application.properties` esterno si aggiungono o sovrascrivono quelle interne al microservizio. Le proprietà interne (es. rootpath dei controller) non sono esposte all'esterno volutamente.
====

== Configurazione comune

Tutti i microservizi condividono le seguenti configurazioni (`microservice-config/application.properties`):

* **URL FHIR Server**: `http://irccs-hapi-fhir:8080/fhir`
* **URL Auth microservice**: `http://irccs-auth:8080`
* **URL Centro Ricerca microservice**: `http://irccs-centro-ricerca:8080`
* **URL Practitioner microservice**: `http://irccs-practitioner:8080`
* **URL Notification microservice (Redis)**: `http://irccs-notification:8080`
* **Keycloak base URL**: `http://irccs-keycloak:8080`
* **Query limit FHIR**: 1000 risorse
* **Timeout connessione**: 120 secondi

== Descrizione dei microservizi

=== irccs-microservice-auth

[cols="1,3"]
|===
|Container |`irccs-auth`
|Immagine |`nexus.infocube.it/org.quarkus/irccs-microservice-auth:2.0.1-SNAPSHOT`
|Porta esposta |— (solo rete interna)
|Config |`microservice-config/application.properties`
|===

Gestisce l'autenticazione e la gestione degli utenti. Espone gli endpoint:

* `POST /fhir/auth/users/signup` — registrazione nuovi utenti
* `POST /fhir/auth/users/token` — ottenimento token JWT
* `POST /fhir/auth/users/logout` — logout
* `POST /fhir/auth/users/forgotPassword` — recupero password
* `POST /fhir/auth/users/updatePassword` — aggiornamento password
* `GET /fhir/auth/users/me` — profilo utente corrente
* `GET /fhir/auth/users/organizations` — organizzazioni disponibili

Gli endpoint di autenticazione sono esclusi dalla policy enforcement Keycloak (`enforcement-mode=DISABLED`).

== HAPI FHIR

[cols="1,3"]
|===
|Container |`irccs-hapi-fhir`
|Immagine |`hapiproject/hapi:v8.0.0`
|Porta esposta |`8080`
|Config |`hapi-fhir-config/application.yaml`
|===

Server **HAPI FHIR R4** che funge da repository centrale per tutte le risorse cliniche. Caratteristiche principali:

* Versione FHIR: **R4**
* Database: PostgreSQL 16 (`postgres-hapi-fhir`)
* Pool connessioni: max 10 (Hikari)
* Modulo **CQL/Clinical Reasoning** abilitato (`hapi.fhir.cr.enabled: true`)
* OpenAPI abilitato su `/fhir/swagger-ui/index.html`
* Ricerca avanzata Lucene: disabilitata (usa Hibernate Search base)
* Cache ricerche: disabilitata (`reuse_cached_search_results_millis: -1`) — necessario per l'eleggibilità
* Bulk export/import: disabilitato
* CORS: `*` (tutti gli origin)

== Frontend (Apache HTTPD)

[cols="1,3"]
|===
|Container |`irccs-httpd-dashboard`
|Immagine |`nexus.infocube.it/i3/irccs/irccs-httpd-dashboard/develop:2.5.9`
|Porta esposta |`80`
|===

Serve la **web application React** (dashboard clinica) e funge da reverse proxy verso i microservizi backend. La configurazione runtime è iniettata tramite il file `httpd-config/config-prod.js` montato come `config.js`.

La documentazione Antora è servita sotto il path `/docs` tramite il volume `./httpd-config/docs`.
