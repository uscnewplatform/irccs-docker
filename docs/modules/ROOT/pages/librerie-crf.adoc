= Librerie CRF — Gestione e Import
:description: Architettura delle librerie CRF (CTCAE, PRO-CTCAE, EORTC) come CodeSystem FHIR su HAPI.

== Panoramica

Le librerie CRF (Case Report Form) utilizzate dalla piattaforma sono distribuite come risorse FHIR standard importate su HAPI FHIR durante l'installazione iniziale.
Il frontend recupera i vocabolari direttamente da HAPI, senza passare da microservizi intermedi.

[cols="1,2,2,2"]
|===
| Libreria | CodeSystem URL | ValueSet URL | Cartella

| CTCAE v4 | `https://ncicb.nci.nih.gov/xml/owl/EVS/ctcae-v4` | `https://ncicb.nci.nih.gov/xml/owl/EVS/ctcae-v4-adverse-events` | `importCrfLibraries/ctcae-v4/`
| CTCAE v5 | `https://ncicb.nci.nih.gov/xml/owl/EVS/ctcae-v5` | `https://ncicb.nci.nih.gov/xml/owl/EVS/ctcae-v5-adverse-events` | `importCrfLibraries/ctcae-v5/`
| CTCAE v6 | `https://ncicb.nci.nih.gov/xml/owl/EVS/ctcae-v6` | `https://ncicb.nci.nih.gov/xml/owl/EVS/ctcae-v6-adverse-events` | `importCrfLibraries/ctcae-v6/`
| PRO-CTCAE v1 | `https://healthcaredelivery.cancer.gov/pro-ctcae` | `https://healthcaredelivery.cancer.gov/pro-ctcae-items` | `importCrfLibraries/proctc-v1/`
| EORTC QLQ-C30 | `https://www.eortc.org/qlq-c30` | `https://www.eortc.org/qlq-c30-items` | `importCrfLibraries/eortc-v1/`
|===

== Struttura di ogni libreria

Ogni cartella contiene:

[source]
----
importCrfLibraries/<libreria>/
├── import-<libreria>.py       # script Python che genera il bundle FHIR da Excel
├── install-<libreria>.sh      # script curl che invia il bundle a HAPI FHIR
└── <libreria>-bundle.json     # bundle FHIR pre-generato (committato)
----

Il bundle FHIR è di tipo `transaction` e contiene:

* `CodeSystem` — termini con proprietà estese (SOC, gradi, codici interni)
* `ValueSet` — tutti i codici del CodeSystem (usato per la ricerca server-side con `$expand?filter=`)
* `StructureDefinition` — profilo FHIR per i questionari che usano la libreria

== Generazione del bundle (solo se necessario aggiornare)

I bundle JSON sono già generati e committati nel repository.
Per rigenerare da un nuovo file Excel:

[source,bash]
----
cd importCrfLibraries/<libreria>
python3 import-<libreria>.py /path/to/file.xlsx
----

Il file `<libreria>-bundle.json` viene sovrascritto.
Committare il file aggiornato e rieseguire lo script di installazione.

=== Requisiti Python

[source,bash]
----
pip install openpyxl
----

== Come il frontend recupera le librerie

Il frontend React (TypeScript) non usa endpoint di microservizio per i vocabolari CRF.

=== URL centralizzati

Tutti gli URL (CodeSystem e ValueSet) sono centralizzati in un unico file:

[source]
----
src/fhir/service/Terminology/CrfConfig.ts
----

Esporta `CRF_CS_URL` e `CRF_VS_URL`, entrambe `Partial<Record<QuestionnaireTypeKey, string>>`.
Ogni altro file del frontend importa da qui — nessun URL hardcoded altrove.

=== Service per tipo

CTCAE v4/v5/v6 condividono un unico service (`CtcaeV6Service.ts`) che accetta l'URL come parametro.
PRO-CTCAE e EORTC hanno service separati.

[cols="1,2"]
|===
| File | Librerie gestite

| `src/fhir/service/Terminology/CtcaeV6Service.ts` | CTCAE v4, v5, v6
| `src/fhir/service/Terminology/ProctcV1Service.ts` | PRO-CTCAE v1
| `src/fhir/service/Terminology/EortcV1Service.ts` | EORTC QLQ-C30
|===

Ogni service:

. Interroga HAPI FHIR con `GET /CodeSystem?url=<CS_URL>`
. Raggruppa i concetti per sezione (SOC / categoria / head)
. Costruisce un oggetto `Questionnaire` FHIR in memoria
. Il `Questionnaire` viene renderizzato nei componenti CRF (builder e questionario paziente)

Il hook `useCtcae` (`src/fhir/hooks/questionnaire/useCtcae.ts`) orchestra la chiamata al service corretto in base al tipo di questionario selezionato.

=== Ricerca server-side

Il dialog di import CRF (`CtcImportDialog`) effettua ricerche tramite `ValueSet/$expand?filter=<testo>` su HAPI usando il `ValueSet URL` della libreria.
Se HAPI non ha Lucene indexing attivo, viene applicato un post-filtro client-side sul `display` dei concetti restituiti.

== Aggiungere una nuova libreria CRF (es. CTCAE v7)

=== 1. Bundle FHIR (irccs-docker)

. Creare la cartella `importCrfLibraries/ctcae-v7/`
. Copiare lo script Python da `ctcae-v6/` e adattarlo ai nuovi URL e al formato Excel v7
. Eseguire lo script per generare `ctcae-v7-bundle.json`
. Creare `install-ctcae-v7.sh` seguendo il modello degli altri script
. Committare bundle JSON e script
. Aggiungere il passo di installazione in xref:installazione.adoc[Installazione e Setup]

=== 2. Configurazione URL (irccs-react-dashboard)

In `src/fhir/service/Terminology/CrfConfig.ts`, aggiungere le entry per il nuovo tipo:

[source,typescript]
----
export const CRF_CS_URL: Partial<Record<QuestionnaireTypeKey, string>> = {
    // ... esistenti ...
    CTC_V7: 'https://ncicb.nci.nih.gov/xml/owl/EVS/ctcae-v7',
};

export const CRF_VS_URL: Partial<Record<QuestionnaireTypeKey, string>> = {
    // ... esistenti ...
    CTC_V7: 'https://ncicb.nci.nih.gov/xml/owl/EVS/ctcae-v7-adverse-events',
};
----

=== 3. Tipo questionario (irccs-react-dashboard)

In `src/fhir/models/Questionnaire.ts`, aggiungere il nuovo tipo all'enum `QuestionnaireType`:

[source,typescript]
----
export enum QuestionnaireType {
    // ... esistenti ...
    "CTC_V7" = "CTC - V7",
}
----

E aggiungere il relativo identificatore in `QuestionnaireIdentifier`:

[source,typescript]
----
"CTC_V7": {
    system: "CTCAE",
    value:  "CTC_V7",
    name:   "CTC_V7"
},
----

=== 4. Service (irccs-react-dashboard)

CTCAE v7 può riutilizzare `CtcaeV6Service.ts` che già gestisce v4/v5/v6.
Aggiungere solo la costante URL e la funzione export:

[source,typescript]
----
// In CtcaeV6Service.ts
const CS_URL_V7 = CRF_CS_URL.CTC_V7!;

export async function buildCtcaeV7Questionnaire(): Promise<Questionnaire> {
    return buildCtcaeQuestionnaire(CS_URL_V7);
}
----

=== 5. Hook (irccs-react-dashboard)

In `src/fhir/hooks/questionnaire/useCtcae.ts`, aggiungere il caso nel `queryFn`:

[source,typescript]
----
if (type === 'CTC_V7') return buildCtcaeV7Questionnaire();
----

=== 6. Aggiornare questa pagina

Aggiungere la nuova libreria alla tabella in cima.
